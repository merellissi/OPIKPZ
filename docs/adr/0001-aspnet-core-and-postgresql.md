# ADR-0001: Серверна частина на ASP.NET Core з базою даних PostgreSQL

Статус: прийнято

Дата: 17.11.2026

## Контекст

Системі потрібен сервер, який приймає події проходу від Android-застосунку, зберігає їх, розраховує відпрацьований час і віддає дані веб-панелі менеджера. Дані мають чітку реляційну структуру: працівники → NFC-картки → події проходу, а звіти будуються запитами з фільтрами за датою й працівником. Обмеження: 8 тижнів на реалізацію, у команді один backend-розробник, розгортання має відбуватися в Docker на сервері підприємства, а API — бути задокументованим для мобільного й веб-клієнта.

## Рішення

Серверну частину реалізувати як REST API на **C# / ASP.NET Core**, дані зберігати в **PostgreSQL**. Схему БД вести міграціями **Entity Framework Core**, документацію API генерувати автоматично через Swagger (OpenAPI). Сервер і БД запускаються в Docker-контейнерах.

## Наслідки

**Переваги:**
- ASP.NET Core має вбудовану підтримку REST API, JWT-автентифікації та Swagger — менше коду «з нуля».
- PostgreSQL безкоштовна, добре працює в Docker і підходить для звітних SQL-запитів з агрегацією часу.
- Міграції EF Core пишуться тією ж мовою, що й сервер, і зберігаються в репозиторії разом із кодом.

**Компроміси та обмеження:**
- Мобільний клієнт пишеться окремою мовою (Android), тож спільного коду з сервером немає — моделі даних доводиться дублювати.
- PostgreSQL потребує окремого адміністрування: резервні копії, оновлення, моніторинг.
- EF Core спрощує типові запити, але складні звіти можуть знадобитися писати на чистому SQL.
- У практичній №3 для міграцій згадувалися Flyway / Liquibase; це рішення їх замінює.
